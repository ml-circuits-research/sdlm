# Design Specification 06: Meta-Reasoning and Introspection

## Explicit meta-state

The system does not expose a private hidden chain of thought. It exposes explicit symbolic objects it computes as part of execution: proof trees, missing-premise analyses, query status, candidate traces, and virtual-circuit audit summaries.

## Reflection

A reflection task asks about a symbolic claim. The KB can report whether it is supported, refuted, both, or unknown. When unsupported, it can inspect rule paths that could derive the claim and report premises currently missing. When supported, it can expose the proof structure.

This is useful because it lets the system reason about the state of an attempted derivation rather than only output a final truth value.

## Runtime introspection

After a request, the runtime stores an audit object derived from the execution trace. A normal SOP task can retrieve and realize fields such as epochs, expansions, reductions, rewrites, selections, and activated circuit names.

Introspection is therefore data produced by the VM, not privileged prose generated by the host runtime.

## Future meta-programming

The current system reports meta-state but does not yet allow arbitrary validated rewrite of a completed proof or general runtime synthesis of new structural subgraphs. A future meta-circuit could propose transformations such as replace, specialize, generalize, fuse, split, or invalidate, but those proposals must pass graph/effect/provenance invariants before commit.
