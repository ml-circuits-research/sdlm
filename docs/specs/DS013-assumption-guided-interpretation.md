## Introduction

Conversation users need useful attempts on incomplete language and enough evidence to correct a wrong interpretation. This specification defines the [assumption](../wiki.html#definition-assumption) and correction contract. The [assumption guide](../assumptions.html) provides executable examples.

## Core Content

Conversation mode must recognize supported conversational intents through read-only SOP routing, then prefer supported installed parsing before bounded, effect-safe SOP interpretation [candidates](../wiki.html#definition-candidate) and punctuation recovery. Several punctuation-separated sentences may execute in one request. A language gap must return an unresolved result with useful clarification and preserve other usable sentences. Actual token classifications remain in the structured gap evidence. [DS017](../specsLoader.html?spec=DS017-conversational-interaction.md) defines conversational [rewrites](../wiki.html#definition-rewrite) and speaker dependencies. Operational failures, invalid semantic rules and exhausted budgets must still roll back the entire request. Strict parser methods, CLI strict mode, chat strict mode and pack acceptance tests retain explicit failure behavior.

[SOP circuits](../wiki.html#definition-semantic-circuit) must own grammatical constructions, lexical transformations, entity-matching thresholds and interpretation explanations. Generic host operations may compare symbols, track support, schedule attempts and map read-only rendering [circuits](../wiki.html#definition-semantic-circuit) over typed evidence. SOP owns the explanatory wording and response policy. No hidden linguistic string language or external neural fallback is part of this contract. Learned canonical competence must precede heuristic fallback.

Each selected [assumption](../wiki.html#definition-assumption) must be recorded before knowledge execution, with an ID, original input or symbol, resulting value, category, reason, responsible [circuit](../wiki.html#definition-semantic-circuit) and qualitative certainty. Available alternatives and structural evidence must be retained. Responses must distinguish those records from reconstructed logical support and unasserted conditional premises. [Candidate](../wiki.html#definition-candidate) scores and heuristic labels must not be presented as calibrated probabilities.

Assertions must retain independent support sets of [assumption](../wiki.html#definition-assumption) IDs. A later supported answer must expose dependencies found in its reconstructed [proof](../wiki.html#definition-proof), including the actual rule used. Rejecting an [assumption](../wiki.html#definition-assumption) must retract facts and rules that have no independent remaining support and recompute closure. Explicit independent support must survive. Rejected name mappings must be excluded from later guesses; other rejected decisions must not be reapplied by the same [circuit](../wiki.html#definition-semantic-circuit) without a changed interpretation.

[Session](../wiki.html#definition-session) [snapshots](../wiki.html#definition-snapshot) must preserve evidence and feedback as ordinary SOP constructors. A rejected [assumption](../wiki.html#definition-assumption) must invalidate saved results that contain it or carry its recorded dependencies. Explicit [value references](../wiki.html#definition-value-reference) must propagate those IDs to derived saved values. Invalidated values may remain inspectable but must fail reference lookup. Knowledge-only export must reject active [assumption](../wiki.html#definition-assumption) dependencies; full [session](../wiki.html#definition-session) export preserves them.

Missing-premise suggestions must cite installed rule structure and remain conditional without asserting their truth. Incomplete reconstructed [proofs](../wiki.html#definition-proof) and aggregate context contributors must be labeled separately from established dependencies. Historical source witnesses, probabilistic calibration and autonomous [circuit](../wiki.html#definition-semantic-circuit) revision remain outside this implementation.

Default bounds are 128 sentences, 12 fallback [candidates](../wiki.html#definition-candidate), two punctuation proposals, 2,048 retained decisions, 100 unresolved inputs and 200 rejection notes. Entity guesses use one edit with adjacent transpositions for names of 4 to 64 characters; equal-distance alternatives use name order and remain explicit [assumptions](../wiki.html#definition-assumption). Suffix recovery handles only the declared final-s rule. [VM](../wiki.html#definition-virtual-machine) budgets apply to the request and to name comparisons. Exported feedback supports external authoring and validation; it does not itself improve [circuits](../wiki.html#definition-semantic-circuit).

SOP policy must identify commands that preserve supplied entity names. Fact and rule assertions, current-value assignments and quantity adjustments must not silently reuse a nearby name. Registered elementary relation vocabulary must not be classified as unfamiliar merely because its predicate is constructed by a [semantic circuit](../wiki.html#definition-semantic-circuit).
